# doccheck — Markdown 文档引用审计工具

`doccheck` 扫描本地 Markdown 文档树，检查相对链接、章节锚点以及从入口
页面无法到达的页面。它只读取文件，绝不修改被检查的文档，也不访问网络。

## 安装与运行

```sh
go build ./cmd/doccheck
doccheck -root ./examples/docs -entry index.md -report report.json
```

参数：

- `-root`：文档根目录（必须是普通目录，不能是符号链接）。
- `-entry`：入口 Markdown 文件，相对根目录或绝对路径均可，必须位于根内
  且是扫描得到的普通 `.md` 文件。
- `-report`：JSON 报告输出路径；报告路径不能指向任何被检查文档。

退出码：

| 码 | 含义 |
|---|---|
| 0 | 无失效链接、无不可达页面；不生成报告 |
| 1 | 存在失效链接或不可达页面；已生成报告 |
| 2 | 输入错误（根目录/入口非法、报告路径非法等） |

## 支持的 Markdown 子集

- **ATX 标题**：独占一行，1–6 个 `#` 后紧跟一个空格，正文为纯文本。
- **简单链接**：行内 `[文字](目标)`，目标不含空白或圆括号。
- 不处理图片（`![..](..)`）、引用式链接与 HTML。
- **围栏代码块**：去除首尾空白后恰为 `` ``` `` 或 `~~~` 的行开启，闭合符
  必须与开启符相同；块内的标题和链接一律忽略。
- **行内代码**：成对单反引号 `` `..` `` 包围的内容忽略；未配对的反引号
  按普通字符处理。

## 锚点规则

1. 转小写，保留 Unicode 字母和数字；
2. 空白转为连字符，其它字符删除；
3. 连续连字符合并，并去掉首尾连字符；
4. 结果为空时使用 `section`；
5. 按文档顺序保证唯一，冲突时追加 `-2`、`-3`……

链接中的锚点（`#` 之后）原样匹配，不再做大小写转换。

## 目标解析规则

- `http://`、`https://`、`mailto:` 链接忽略。
- 其余目标 = 相对路径 + 可选 `#锚点`；路径相对所在文件解析。
- 空路径表示本文件；`a.md#` 的空锚点视为未指定。
- 允许 `.`/`..` 规范化，但结果不能越出根目录（`outside_root`）。
- 拒绝绝对路径、反斜杠、查询串（`?`）等（`illegal_target`）。
- 不做百分号解码；目标路径任一级为符号链接均判 `illegal_target`。
- 本地目标必须是存在的普通文件（否则 `file_missing`）；带锚点时目标
  必须是 Markdown 且锚点存在（否则 `anchor_missing`）。

## 页面图与不可达页面

有效的 Markdown 目标构成有向图，从入口沿有效链接做 BFS，未被访问的
扫描文件列为不可达页面（自链接不增加新页面，循环安全处理）。

## 报告格式

报告按源文件、行号、同行顺序列出链接，字段包括 `source`、`line`、
`column`、`target`、`path`、`anchor`、`status`；`unreachable_pages`
按相对路径排序；`counts` 给出各状态计数（含 `unreachable_pages`）。
示例输出见 `examples/report.json`。

## 测试
